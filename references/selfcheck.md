# 自检

给人看之前做一遍；大改（换结构、换开头、改时长）之后重做。不单独写报告：结果用一张小表放在交付的那条消息里，只列没达标的和打算怎么改。

## 稿子（配音之前）

`python tools/tts/script_measure.py videos/<名字>/lines.js`，对照 `writing.md` 第二部分：

| 项 | 目标 |
|---|---|
| 句均字数 | 20–30 |
| 逗号间小句 | ≥ 7 字 |
| 8 字以内的句子 | ≤ 15% |
| 别的声音开口 | ≤ 3 次 |
| 对观众说「你」 | ≥ 2 处 |
| 每块时长 | 40–75 秒（配音好了以后按时间轴算） |
| 笑点 | 每 100–180 字一处，挂在句尾；最重的一块里没有 |
| 最后一句 | 平的 |

再做两个不靠数字的检查：把笑点小句全删掉，剩下的还是不是一个完整的故事；只听不看，说不说得出「谁、在哪、手里拿着什么」。

科普讲解再加两问（`writing.md` 第六部分）：**一个完全不懂的人看完，能不能用自己的话把每个概念复述一遍？一个已经懂的人看完，有没有学到至少一个新的事实或细节？** 任何一个答「不能 / 没有」，就是稿子还没写完。

**送配音之前，交给别的代理审一遍**（查三样：逻辑强不强、听不听得懂、有没有画面感）。自己写的稿子自己看不出哪里听不懂。做法：

- 把台词导出成纯文本（不带编号），派两个互不通气的代理，只给稿子和背景，不给你自己的判断：
  - **第一次听的普通观众**：按顺序一句一句只读一遍，标出在哪句掉队（没解释的词、指代不清、听不出边界的原话、同音）；最后**不看稿复述**——这条片子讲了什么、每个关键词是什么、结论是什么。复述不出来的地方就是没讲清的地方，比任何意见都准。
  - **编辑**：先读 `writing.md`，再分三节审——逻辑（是不是一条链、开头的问题结尾答了没有、前后矛盾、硬凑的对应）、能不能听懂、有没有画面感（逐句问摄像机拍不拍得到）；另外标「口气比证据硬」的句子，列出砍 300 字砍哪里。
- 要求每条意见引用原句、给改法、按严重程度排，不要客套。完整意见让它写进文件，回话只要最严重的几条。
- 按意见改完如果动了结构，**再派一个新的代理复审**（不给它看前一轮的意见），直到复述对得上。审稿意见存进这条片子的 `docs/research/`。
- **开头单独盲选。** 长片的开头写三四个不同起手的版本（先讲一件事 / 先问一句 / 先报热点……），连同你自己最想用的那个，不标偏好，交给一个扮「刷到这条的普通人」的代理：每个版本只读一遍，说出前 3 秒听到什么、在哪个字会划走、前 10 秒以为这条讲什么、这一段的核心说不说得出来、哪些词是空降的，最后排名。它说不出核心的版本不用；它指出的共同毛病（核心句太晚、比方空降、报幕太长）在选中的版本里一起改掉。
- 审稿的代理说的也不全对：涉及事实的改法（比方、数字、谁说的）照样回出处核；和委托人明确要的东西冲突时，以委托人为准。

**画面也找别人看一遍。** 抽三十来帧拼图，交给一个代理只看画面挑「简陋在哪」（做法见 `picture.md`「画面别简陋」）。最常见的三样：主体太小、一个机位到底、背景只有一层。

**事实在配音之前核完。** 稿子里每一处「谁在哪天说了什么、数字是多少」都回到一手出处读一遍原文再送配音，转述别人的话尤其要对着原句。别的讲解者说过的事实不算出处（一条参考稿里的「正文只出现一次」「有别的叫法就跟着用」，回原文一看一句核实不了、一句意思不对，配音做完才发现，只好改词重录）。核实不了的写成两头都成立的说法，或者删掉。

## 配音

`vo_qa.py` 没有读错（拿不准的换识别模型再看一次：两个模型在**同一个字**上听错才算读错，各错各的多半是识别的问题）。讲述者和别的声音的音高拉得开。加过电音（`voice_fx.py`）要再核对一遍。报告里的「多音字待查」逐条看：无声调拼音比对认不出「重来」读成了 zhòng。

## 画面

每个镜头抽一帧拼图（`contact_sheet.py`）：不出框、不互相压、深底上看得清、字幕不压角色、画面没有比声音先露底。

再问一句：**每个被讲到的机制，画面上有没有一个在动的演示？**「字和线条一个个出现」不算演示；要看得见东西在流动、变化、被剪掉、被找出来、被退回。讲述者要在画里演（走过去、指着、拿道具、做表情），不能整片杵在角落。抽一帧「做完」的状态之外，每个机制再抽一帧「正在动」的中间状态看。渲染器没有打印 `page warning`（`wt()` 找不到词）和 `page error`。

讲述者亲手做事的片子（`lib/actor.js`）：`node render.mjs videos/<名字> --sweep` 整条走一遍，页面报错为 0；「被拉长的胳膊」里 400 以上的逐个去看那一帧。再数一遍：有没有哪一幕它只是站着。上半屏有没有一大片空着。

## 完播扫描

```bash
node render.mjs videos/<名字> --sound-only
python tools/retention_scan.py <名字> --safe <开头、中段、结尾各一帧的毫秒>
```

| 项 | 标准 |
|---|---|
| 第一句开口 | ≤ 0.5 秒；第 0 帧画板上已经有东西 |
| 前 30 秒 | 没有 ≥ 4 秒的静止段 |
| 全片 | 没有 ≥ 8 秒的静止段 |
| 最后一句之后 | ≤ 4 秒 |
| 遮挡区 | 字幕、标题、关键字不进平台遮挡区（`safe.png` 是估计值，发布前真机确认） |
| 平台时长 | 看 `PROFILE.md` 里写的平台：有的平台超过 3 分钟不推荐给新受众，有的平台 2 分钟以上算中长视频另有扶持 |

静止扫描裁掉了底部字幕带，只量画面。「静止」可以是有意的（让人读一张卡、让一句话沉一下），但不超过 8 秒。叙述片不追求每秒都在动；追求的是没有哪一段画面和正在说的话脱了节。

## 声音

`sound.py` 打印的音效数：讲述者在画面里动手的片子，每分钟几十到一百多个才对（脚步、笔声占大头）；只有个位数，就是动作是哑的——回去看 `sound.md` 的音效一节。打印里有 `?种类` 说明场景要了一个 `lib/sfx.py` 不认识的声音。

峰值 −1 dBFS 附近、没有削波；配乐比人声低 10 dB 以上；几个声音响度相差 2 dB 以内（量法见 `sound.md`）。

- [ ] 片尾有平台要求的标注（AI 生成内容等）。
- [ ] 稿子、来源、数字记进了 `videos/<名字>/docs/<名字>.md`。
- [ ] 交付的话里写了：片长、分几块、笑点在哪、自检的数字、哪些地方只有人能判断（音色、语气、配乐音量、好不好笑）、怎么报问题（秒数）。
