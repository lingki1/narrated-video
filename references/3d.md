# 三维底图：Blender 出一次分层，动在网页里

要纵深的大景（群山、云海、水面、城市远景），二维的整屏插画撑不起来：镜头一推，远近不分开，就是一张被放大的画。这里的做法是用 Blender 把一幕建成三维的水墨场景，**但不逐帧渲视频**：只渲一次，按远近切成几片带透明的底图；镜头、表演、特效仍然写在网页里，出片仍然是 `render.mjs` 从网页一帧一帧截。

Blender 只走命令行（`blender -b`），不开界面、不手工摆东西：一幕就是一个短脚本，改了重跑。所有模型由脚本生成，不下载模型和贴图。

## 什么时候值得上三维

| 值得 | 不值得 |
|---|---|
| 镜头要往画里推、横移时远近要拉开 | 讲机制的示意、图表、界面、对话：二维模板更快也更清楚 |
| 大远景：主体是景，角色只是景里的一个点 | 角色的戏是主体、要走很多步、要拿很多道具（`lib/actor.js` 的二维角色能做的事多得多） |
| 要一个有冲击力的开场或转场（一段真正穿过场景的飞行） | 只剩半天时间 |

- 它不是第 17 种模板，是「一幕的底图」：时间轴、字幕、配音、音效、片尾、预览、出片都还是内核那一套（`picture.md`）。一条片子可以只有一两幕用它。
- 代价要先说给委托人：一幕从建模到在网页里演完，按一两个小时、二三十次渲染估；机器上要有 Blender 5（用到 5.x 才有的合成器接口；在 5.2 上跑通）。路径写在 `video.config.json` 的 `blender`，或者环境变量 `BLENDER`，或者让它在 PATH 里。
- 风格是设色水墨：墨的浓淡和留白是主体，淡彩罩在墨上。它和技能别处的「纯色平涂」不冲突：角色和网页里画的东西（太阳、灯、落叶）仍然是平涂的。

## 整体思路

1. **Blender 渲两样**：一张静帧（定稿看这个），和按远近切好的分层（每片一张带透明的图；角色和会动的东西各自单独一张）。
2. **`lib/plates.js` 在网页里把分层叠回去**，给它一个相机的位移（前进、横移、升高），它按每一层的远近算缩放和滑动：近的扫过去，远的几乎不动。
3. **会动的东西在网页里动**：角色的图绕脚、绕肩转；太阳、鸟、落叶、灯火在网页里画，挂在场景给的锚点上；一切都是 `t` 的纯函数。
4. **只有相机真的要穿过场景的镜头才逐帧渲**（`fly()`）：尽量短，落点和下一幕分层的机位重合，网页从最后一帧接到分层上。

为什么不整条逐帧渲：一幕分层十几秒就出完，之后改镜头、改表演都不用再碰 Blender，几秒钟看到结果；逐帧渲 1080p 大约零点几秒一帧，三分钟的片子五千多帧就是一小时上下，改一个镜头重来一遍。委托人要看的是能改的预览，不是等出来的成片。

## 库（`lib3d/inkkit.py`）

场景脚本开头 `from inkkit import *`，结尾 `finish(slabs)`（或 `fly(…)`）。读一遍库的全文再动手，它不长。

| 要什么 | 用什么 |
|---|---|
| 墨 | `ink(name, base, shade, crevice, top, edge, streak, blot, …)`：墨是着色器，不是贴图。一个点上有多少墨 = 底墨 + 背光的一面 + 石缝（`crevice`，`ao` 管多宽算缝）+ 靠近顶部 + 转过去的轮廓 + 两种噪声（拉长的皴 `streak`、圆的墨点 `blot`）+ 岩石的节理 `crack`；再按离相机的远近减淡（`far=(从, 到), far_k`） |
| 淡彩 | `wash=[(颜色, 多少, 哪里), …]`，哪里 = `'top'` 山头 / `'low'` 山脚 / `'sun'` 向光面 / `'shade'` 背光面 / `'all'`。颜色是乘在墨上的，墨还透得出来；远山的墨淡了，颜色还在。现成的颜色：`AZURITE` 石青、`MALACHITE` 石绿、`OCHRE` 赭石、`INDIGO` 花青、`GAMBOGE` 藤黄、`ROUGE` 胭脂 |
| 雾、云 | `mist()` 一整箱雾（云海），`cloud(中心, 半径)` 一团立起来的云。它们是「吸收多少就发多少纸色的光」的体积，所以雾厚的地方正好是纸色：**留白就是纸** |
| 形状 | `mountain(name, [(x, y, 高, 半径), …], base, seed, mat)` 一座带沟壑和台阶的山；`grid_mesh()` 任意高度函数铺成的面；`tube()` 一笔圆头的线（树干、绳子）；`strokes()` 成簇的短笔触（松针、草）；`lathe()` 车出来的形；`box / ball / quad / disc`；`pine()` 一棵斜松；`mirror()` 不用光线追踪的倒影 |
| 平涂的东西 | `flat(name, 颜色)` 不受光的纯色；`toon(name, 暗, 亮)` 两档平涂 |
| 角色 | `buddy(location, facing, name, card, arm, lean, gaze, look)`：`lib/buddy.js` 那个现成角色的三维版，高约 2.6 个单位，`look` 改配色。自己的角色照它的写法另写一个函数 |
| 光和相机 | `sunlight(elevation, azimuth)` 唯一的一盏灯；`camera(location, aim, over=(横, 竖))` |
| 交给网页的 | `anchor(name, 点, size)` 记一个点；`actor(name, root, exclude, pivot)` 这一家子单独成层；`span(obj)` 贯穿每一片的东西（水面、地面） |
| 出图 | `finish([(片名, 近, 远), …])`；`fly(pose, 秒数)` |

出图时合成器再做两件事：一道笔触滤镜（`kuw=`，把渲染的光滑抹成笔意），和按深度的跳变勾一道墨线（`edge=`，远处不勾）。角色的层不过这两道，保持利落。

## 写一个场景脚本

工程模板里有一个最小的例子：`templates/_3d/blender/peaks.py`（几座山、一片云海、一个角色、一个留给网页画的太阳）和它的网页一侧 `templates/_3d/scene.js`，旁边的 `flyover.py` 是同一个布景上的一段飞行。抄进一条片子就能跑：

```bash
python tools/new_reel.py 01-name "标题"                 # 借任意一个模板的壳（index.html、台词、配乐）
cp -r templates/_3d/. videos/01-name/                   # blender/peaks.py、blender/flyover.py，并换掉 scene.js
python tools/shot3d.py 01-name peaks still              # 先看静帧
python tools/shot3d.py 01-name peaks layers             # 再出分层
node render.mjs videos/01-name --stills 0,9000,20000    # 网页里叠起来的样子
```

一个场景脚本从上到下是这几段：

1. **墨**：一档远近一种材质。越近墨越重、皴越粗；越远越淡、越偏青蓝。噪声的尺度（`streak_scale`、`blot_scale`、`wash_scale`）跟着距离缩小：远山本身大，纹理是按世界单位算的。四档怎么配，看例子里的 `M_NEAR / M_MID / M_FAR / M_BACK`。
2. **布景，由近到远**：山脚压在雾面以下（`base` 取负数），露出来的只有山头。角色要站的地方得是平的（例子里的 `bluff()`：自己写一个高度函数交给 `grid_mesh()`）。
3. **雾和云**：`mist()` 的箱子要把相机和所有会被看到的地方都装进去（飞行的起点也在里面，否则会看见箱子的一面墙）。
4. **光**：`sunlight()`。默认不投阴影，别打开（见「踩过的坑」）。
5. **锚点和角色**：网页要挂东西的地方、角色站的地方、他要走的路上的几个点，都用 `anchor()` 记下来。
6. **相机和出图**：`camera(…, over=…)`，`finish([...])`。

几条规矩：

- **单位**：相机朝 +Y 看，+X 向右，+Z 向上。画面是 35 毫米镜头的 1920×1080，一个单位在距离 d 处是 `1867 ÷ d` 个像素：角色离相机 26 个单位，在画面里高约 190 像素。大景的主体是景，角色一两百像素高就够，但要读得出是它（深色的身体衬在留白上）。
- **机位基本平视**。网页里的镜头只会平移（前进、横移、升降），不会转头；要转头、要绕着东西转的镜头，分层做不了，归 `fly()`。
- **先静帧，后分层**。每次渲完自己看图，当美术指导挑毛病：构图、墨色的层次、哪里糊成一片、哪里露了网格的边。静帧定了再出分层。
- **留给网页画的东西**（要动的太阳、灯）在分层里不建，在静帧和飞行里建：`if MODE != 'layers': …`。传给 `shot3d.py` 的任何 `key=value` 都落在脚本的 `OPT` 里，可以自己认几个开关（例子里的 `sun=0`）。
- **要像某个真实的地方**，就抓它让人认得出的几样特征自己建模、自己摆构图，不描别人的照片和画。
- 往库里加东西时，模块级的变量别起 `PX`、`PY` 这种短名字：场景脚本是 `import *` 进来的，会和场景自己的变量撞。一幕自己用的帮手写在自己的脚本里；别 import 另一幕的场景脚本（会把那一幕也建出来），要共用布景就像 `flyover.py` 那样，让布景文件在被 import 时只建不渲。

## 切片、角色、锚点、余量

**切片** `finish([('near', 0.1, 50), ('mid', 50, 172), ('far', 172, 420), ('back', 420, 3000)])`：按离相机的距离切，近的在前，四到六片。

- **切口落在东西之间的空当**，别切过一座山或一团云：两半会按不同的远近滑开。一样东西归它包围盒中点所在的那一片。
- 雾属于每一片，每片只留自己那一段；云默认和同一片的山一起渲，谁挡谁由渲染器决定，和静帧一致。`clouds=1` 才让云单独成层（能自己漂），代价是它整个叠在同片的山前面，山会被冲淡。
- 一片的 `depth`（网页按它算滑动的多少）默认取片里东西的平均距离，可以写成第四个数自己定。
- 水面、地面这种从近铺到远的东西用 `span()`：每一片留它在自己范围里的那一段。

**角色和会动的东西单独成层** `actor(name, root, exclude, pivot)`：`root` 和它底下的东西单独渲一张。船、旗、能摆的树枝、角色，凡是网页要让它自己动的都这样。

- `buddy()` 自动注册两层：身体 `<name>` 和右臂 `<name>-arm`（绕肩转），外加锚点 `<name>-feet`。手里的东西 parent 到返回的 `arm` 上，就跟着手臂一起成层。
- **换姿势 = 同一个位置再建一个**（`name='buddy2'`），各自成层，网页里切换显示哪一个。
- 不想做迈腿：让近处的东西挡住脚（挡脚的那样东西要落在比角色更近的一片里）。
- 角色的层按它**脚下那片地**的远近滑动，否则脚会在地上滑。`plates()` 默认找离它最近的地面层，不对就用 `stand: { 角色层: 地面层 }` 指定。

**锚点** `anchor(name, 点, size)`：`layers.js` 里得到 `{ x, y, depth, r }`——它在画面里的像素位置、离相机多远、`size` 换算成的像素。网页里的太阳挂在哪、鸟从哪飞出来、角色沿哪几个点走，都从这里读，不在网页里猜坐标。

**余量** `camera(…, over=(ox, oy))`：分层画得比画面宽 ox 倍、高 oy 倍，多出来的就是镜头能动的范围。相机右移 x、升高 y、前进 z（场景单位），最近那一片（`depth` = d）还盖得住画面的条件是：

```
|x| ≤ 0.514 × ((ox − 1) × d + z)        |y| ≤ 0.289 × ((oy − 1) × d + z)        后退时 z ≥ −(ox − 1) × d
```

横移多的幕把 `ox` 给到 1.5–2；只是轻推的 1.25 就够。余量越大图越大，别无谓地给。`still wide=1` 渲一张带余量的静帧，看多出来的那一圈里有没有露出网格的边、有没有空掉一块。分层默认按 1.5 倍精度出（`px=1.5`），因为网页会把它放大。

## 网页里怎么叠、怎么动

```js
import { createFilm, E, el, seg } from '../../lib/film.js';
import { plates } from '../../lib/plates.js';
import META from './img/peaks/layers.js';                      // shot3d.py 写的：每一层的图、远近、位置，和锚点

const film = createFilm({ lines: LINES, durations: D, size: [1920, 1080] });
const { T } = film;
// 在 film.start() 之前就建：图片马上开始加载
const sc = plates(META, new URL('./img/peaks/', import.meta.url));
const A = sc.anchors; const body = sc.byId.buddy; const arm = sc.byId['buddy-arm'];
// slot(depth)：在这个远近插一层空的，里面按画面像素摆自己的东西，它跟着镜头走
const sun = el('div', '', '', `position:absolute;left:${A.sun.x - A.sun.r}px;top:${A.sun.y - A.sun.r}px;width:${2 * A.sun.r}px;height:${2 * A.sun.r}px;border-radius:50%;background:#D8342B`);
sc.slot(A.sun.depth, 'sun').append(sun);

film.start({
  build() {
    const UP = film.wt('L01', '某个词');
    film.shot(0, T.card, sc.node, (t) => {
      const k = E.sineInOut(seg(t, 0, T.end));
      sc.place({ x: 2 * k, y: 0.3 * k, z: 3 * k }, t);          // 相机离开 Blender 机位多少：右、上、前（场景单位）
      const on = seg(t, UP, UP + 300) * (1 - seg(t, UP + 1700, UP + 2100));                  // 这一下动作：起、停住、落
      const hop = `translateY(${(-16 * Math.abs(Math.sin((t - UP) / 190)) * on).toFixed(1)}px)`;
      body.img.style.transform = hop;                            // 身体：变换原点在两脚中间
      arm.img.style.transform = `${hop} rotate(${(-28 * on).toFixed(2)}deg)`;   // 手臂：先跟着身体移，再绕肩转
    });
  },
});
// 片子「准备好了」= 内核自己的准备 + 每一张图都进来了
window.sceneReady = Promise.all([window.sceneReady, sc.ready]).then(() => window.renderAt(0));
```

- `plates(meta, base, { stand, drift })` 返回 `{ node, byId, anchors, slot, place, project, ready }`。`node` 交给 `film.shot()`；`byId[层名]` 里 `.el` 是这一层、`.img` 是那张图、`.move` 是它按多远来滑动（可以改）。
- **表演写在 `layer.img.style.transform` 上**，别动 `.el`（那是镜头用的）。图的变换原点已经设好：身体是两脚中间，带 `pivot` 的部件是它的轴。**身体和手臂是两张图，移动要两张一起移**，否则会脱开。
- `slot(depth)` 插在「比它近的第一层」后面。想让一样东西在某一片的后面，`depth` 得比那一片的大（片的 `depth` 是平均距离，不是它的后沿）；或者插好以后改 `sc.byId[名字].move`。
- `project({ x, y, depth }, cam)`：一个锚点在当前镜头下跑到了画面的哪里（给不跟镜头走的那层东西对位用）。
- **一切都是 `t` 的纯函数**：不用计时器、不用 `Math.random()`（要随机用 `hash(i)`），拖到任何一刻画面都对。缓动只有 `lib/motion.js` 里那几个名字，写了不存在的会在那一帧抛错。
- **声音**：部件是在 `film.start()` 之前建的，那时还没有时间轴，这时候报的声音会被悄悄丢掉。写在 `render(t)` 里随画面报，或者让部件把要响的时刻攒成 `[[毫秒, 种类], …]` 返回，在 `build()` 里统一 `sfx()`。
- **自己加的 `<img>`** 写上 `max-width:none;max-height:none`（见「检查」第 6 条），它的加载也要并进 `window.sceneReady`。
- **分层底图是静的**。一幕里要有几样东西一直在动（漂的雾、水纹、鸟、落叶、摆动的枝条、闪的灯火），外加一个亮点时刻；否则就是一张会滑的画。角色照旧每一幕亲手做一件事。
- **过场不硬切**：`python tools/mist_plate.py <名字>` 生成一张比画面宽的云雾图（`img/mist.webp`）和一块纸纹（`img/grain.png`），都是噪声算出来的。两幕之间让云雾横着漫过画面，盖满的那一刻换底下的幕；纸纹铺在整个画面最上面，把三维的图和网页画的东西压成一张纸上的画。
- 幕多的片子，一幕一个模块：`(film, T, { from, to }) → { node, from, to, ready, cues, render(t) }`，`scene.js` 只负责排时间、`film.shot()` 和把各幕的 `ready` 并起来。给片子留一个「只看这一幕」的开关（读 URL 里的一个参数，`render.mjs --query` 传进去），一幕一幕地做和查。

## 一段飞行

`fly(pose, 秒数, each=…)`：`pose(t)` 返回 `(相机位置, 看向哪, 侧倾角度)`，库把它烤成关键帧（运动模糊才看得见一帧之内的移动），逐帧渲成 `f0001.jpg …`。

```bash
python tools/shot3d.py <名字> flyover fly step=15 samples=32    # 先每 15 帧渲一张
python tools/sheet3d.py <名字> flyover                          # 拼成一张图，看路线
python tools/shot3d.py <名字> flyover fly samples=32            # 定了再渲全
python tools/pack_frames.py <名字> flyover q=80 per=2           # 两帧并一张 WebP → img/flyover/a000.webp … + frames.js
```

```js
import FR from './img/flyover/frames.js';
function flight(film, base) {
  const cv = el('canvas', '', '', `position:absolute;left:0;top:0;width:${film.W}px;height:${film.H}px`); cv.width = FR.w; cv.height = FR.h;
  const ctx = cv.getContext('2d'); let shown = -1;
  const atlas = FR.files.map((f) => { const im = new Image(); im.src = new URL(f, base).href; return im; });
  const ready = Promise.all(atlas.map((im) => im.decode().catch(() => null)));
  const render = (t, from) => {                                  // from：第 1 帧在片子里的毫秒
    const i = Math.max(0, Math.min(FR.count - 1, Math.round(((t - from) / 1000) * FR.fps)));
    if (i === shown) return;
    shown = i; ctx.drawImage(atlas[Math.floor(i / FR.per)], (i % FR.per) * FR.w, 0, FR.w, FR.h, 0, 0, FR.w, FR.h);
  };
  return { node: cv, ready, render };
}
```

- **飞行和分层用两个场景脚本**，共用的布景放在被 import 的那个文件里（例子：`flyover.py` import `peaks.py`）。布景改了，两边都要重出。
- **落点 = 下一幕的机位**：`pose()` 的最后一刻正好是分层那一幕 `camera()` 的位置和朝向，镜头的焦距也回到 35。网页在那一毫秒从最后一帧换成分层，两边要是同一幅画（「检查」第 4 条）；网页里画的东西（太阳的颜色、大小、光晕）要照着 Blender 里的那一份画。
- 飞得快的时候勾线不会跟着运动模糊糊开，会发硬、会抖：在 `each(t)` 里把它减淡（`STATE['edge'].default_value = EDGE * 0.2`），慢下来再还回去。广角一点（`STATE['cam'].lens = 24`）更有速度感，落地前回到 35。
- 路线贴着东西飞才有速度：每一拍有一样东西擦身而过，比在空旷处飞得再快都管用。节拍和配乐对上。
- 图是几百张，约 50 KB 一帧；手机上实时播放可能跟不上，给预览时说明。托管的地方限制文件个数时把 `per` 调大。

## 命令和耗时

```bash
python tools/shot3d.py <名字> <场景> still [wide=1] [key=value …]     # → out/shots/<场景>.png（wide=1：-wide.png）
python tools/shot3d.py <名字> <场景> layers                           # → img/<场景>/*.webp + layers.js；out/shots/<场景>-check.png
python tools/shot3d.py <名字> <场景> fly [from= to= step= shutter= jpg=]   # → out/shots/<场景>/f0001.jpg …
python tools/sheet3d.py <名字> <场景> [pick=16]                       # 飞行的抽帧拼图
python tools/pack_frames.py <名字> <场景> [q=80 per=2 fps=30 t0=0]    # 飞行的帧 → 图集 + frames.js
python tools/mist_plate.py <名字>                                    # 过场的云雾、纸纹
python tools/motion_strip.py <名字> <起毫秒> <止毫秒> step=150 crop=x,y,w,h name=<段名> [query=k=v]
python tools/frame_diff.py <名字> <毫秒A> <毫秒B> name=<接缝名> [box=x,y,w,h]
```

场景在 `videos/<名字>/blender/<场景>.py`。常用的 key：`samples=48` 采样、`px=` 每个画面像素渲几个像素、`kuw=3.2` 笔触滤镜的大小（0 关掉）、`edge=0.85` 勾线的浓淡、`fog=0` 不要雾（调山形时快）、`post=0` 不做后期。

量过的数量级（1080p，一块桌面独立显卡）：静帧约 5 秒，一幕分层十几秒，飞行约 0.6 秒一帧。显卡被别的任务占着时会慢几倍到十倍，偶尔还会失败：等一会儿重试，别急着改代码。

## 检查

静帧一张张看不出层和层错位、走路滑脚、手臂脱开，稀疏的缩略图更看不出。给人看之前这六条都要过：

1. **分层叠回去和静帧是同一幅画**。`shot3d.py … layers` 出完会把各层叠回去存成 `-check.png`，并和同名的静帧比：`stacked layers vs the still: mean difference …`。静帧要先渲，而且得是「不带留给网页画的东西」的那一张（例子里 `still sun=0`）。差值在两三以内是同一幅画；大于 4（工具会提醒）就放大对着看，找到原因再往下做。角色的几个姿势都叠在检查图里，那一块不算。
2. **余量够不够**。镜头走到最远的那两头各抽一帧：有没有露出层的边、空掉一块、露出本来被前一片的雾盖住的东西。
3. **每一段动作切成连续帧放大看**：`motion_strip.py <名字> 5000 9000 step=150 crop=…`。看脚滑不滑、手臂和身体脱没脱开、压扁拉长得过不过分（落地压扁一点像落地，压多了像图坏了）。
4. **接缝两边量差**：飞行落到分层、一幕换一幕的那一刻，`frame_diff.py <名字> <前一毫秒> <后一毫秒>`，差值和第 1 条一个标准；它会出一张「左 | 右 | 差在哪」的图。
5. **整条走一遍**：`node render.mjs videos/<名字> --sweep --step 250`，页面报错为 0。
6. **发布到哪儿，就在哪儿的页面外壳里渲一遍，和片子自己的渲染逐秒对比**。预览被嵌进别的页面时，宿主的全局样式会改你的画面：最常见的是 `img { max-width: 100% }` 把比容器宽的分层底图横向压扁，山挤成一半宽、挡脚的那层被挤走、角色悬空。片子自己的渲染页没有这条规则，所以自己抽的帧全是好的。`plates.js` 已经给每张图写了 `max-width: none`；你自己加的图也要写，并且仍然要在宿主的外壳里实际渲一遍对过才算数。

交付时明说你看不了的：动起来顺不顺、笔触滤镜动起来闪不闪、各层滑动时有没有撕开、手机上卡不卡。这些只有人看得出，请对方报秒数。

## 一幕交给一个代理

幕多的时候可以一幕派一个后台代理，主会话验收。写给代理的须知里要有：

- 它只写两个文件：这一幕的场景脚本和这一幕的网页模块；库和别的幕一律不改，缺的帮手写在自己的文件里，值得进库的在汇报里提。
- 委托人对画面说过的要求，逐条列出。
- 上面的规矩里和它有关的：先静帧后分层、切口、角色成层、锚点、余量、纯函数、注释单独成行。
- 它的时间窗（这一幕从几毫秒到几毫秒、头尾各有多久被过场盖着）和可以用的声音种类。
- 约束：不下载、不渲视频、渲染次数的预算、显卡是共用的。
- 交工要什么：静帧、带余量的静帧、分层检查图、整幕一秒一帧的连续帧图、每段动作的连续帧图的路径；分层和静帧的差值、`--sweep` 的结果、层和锚点的名字；这一幕按时间发生了什么；它自己看不了的地方。

代理说「检查过了」不算数：差值和连续帧图主会话自己再看一遍。

## 踩过的坑

| 现象 | 原因 | 规矩 |
|---|---|---|
| 分层叠回去比静帧平，或者影子更黑更硬 | 出分层时把灯也藏了；或者开了投影（渲染器按相机的范围配阴影贴图，一片的范围窄，影子就和整幕的不一样） | 灯每一片都亮着（库已经这样做）；`sunlight()` 不投影，明暗靠墨的着色器 |
| 山被同一片的云冲淡，飞行落到分层时雾和山对不上 | 云单独成层以后，叠的时候整个盖在同片的山前面 | 云和山同片一起渲（默认）；非要云自己漂才 `clouds=1` |
| 一座山、一团云滑成两半 | 切口切过了它 | 切口落在空当；量一下每样东西离相机多远再定 |
| 雾里有一道淡淡的折线；镜头一推才露出来 | 勾线只认深度的跳变，不认雾：雾下面山脚的网格边照样被勾出来。靠后的片里，这些地方平时被前一片的雾盖着，镜头走远了就露出来 | 山脚压深，或者藏进别的山里；镜头的两头抽帧看；推得不要太深 |
| 隔着云看得见后面山的轮廓 | 同上 | 可以当效果用（穿云的一瞬）；不要就把那团云加厚、把 `edge=` 调低 |
| 角色的脚在地上滑 | 角色的层按自己的远近滑，和脚下的地不一样 | 跟脚下那片地（`plates` 默认如此；不对用 `stand` 指定） |
| 手臂跑到身前的东西后面 | 手臂层的远近取的是肩膀；侧身时可能比身前的东西还远 | 出分层后看一眼各层的顺序；不对就在网页里把那一层挪到上面（`sc.node.append(sc.byId[名字].el)`） |
| `wash` 的山头色、山脚色上错了地方 | `'top'` / `'low'` 按物体的包围盒算，几座山合成一个网格时按整体算 | 一座山一个物体 |
| 画面少了东西，不报错 | 把注释接在一行很长的代码中间，后半行被吞掉了 | 注释一律单独成行 |
| 预览页里每一幕都被压扁、对不齐 | 宿主页面的全局样式压了图的宽度 | 图上写 `max-width: none`；在宿主的外壳里渲一遍对比（「检查」第 6 条） |
| 抽出来的帧是白的，或者少一层 | 图还没进来就截了 | 每个部件的 `ready` 都并进 `window.sceneReady` |
| 重出分层以后，同名场景的飞行图集没了 | `layers` 会清掉 `img/<场景>/` 里旧的图和索引 | 飞行和分层用不同的场景名 |
| 飞行里勾线发硬、抖 | 勾线不跟运动模糊 | 快的时候减淡（`STATE['edge']`） |
| 飞行的第一帧看见一面雾墙 | 相机在雾的箱子外面 | 箱子把整条路线装进去 |
| 卡片上的中文是空的 | Blender 自带的字体没有中文 | 三维里只写拉丁字母和数字；中文在网页里叠 |
| 改后期的阈值总对不上 | 合成器在线性光下算：纸色的亮度约 0.85（屏幕上看是 0.93） | 按线性值想 |
