# 配音

配音在本机合成、自动查读错；**音色和语气好不好只有人能判断**。交付时说清楚哪些是没法替人听的，并请对方按秒数指出问题。

## 声音从哪来

- **用文字描述设计的声音**（`tools/tts/voice_design.py`）：写一段描述（年龄、音色、语速、口吻、不要什么），每个方向出两条，挑一条约 10 秒的当这个声音的参考。它不属于任何真人。
- 别人的声音只有说话人明确同意才用：开放许可的数据集、公有领域录音、有授权的配音。创作者、明星、动画和游戏角色的声音不克隆。
- 不要请委托人录自己的声音，除非他主动提。
- 一个声音一条参考，全片不换。按句子换语气参考拼出来的整片，听的人会觉得「很差」。
- 挑声音没人可问时：几个声音的音高要拉开（量中位音高，互相差 40 Hz 以上），底噪低的优先；在交付时写明「这个声音是我按测量挑的，没人听过」。

描述怎么写（例）：
> 二十出头的年轻男声，音色清亮，语速偏快，嘴碎、爱吐槽但不刻薄，像在跟熟人讲自己干的蠢事；句尾自然下落，不播音腔，不撒娇。

## 生成

`voices.json`（项目根目录）写每个声音字母用哪条参考、参考里说的是什么字。然后：

```bash
python tools/tts/vo_all.py <名字>                 # 模型只加载一次，所有声音一起出；已有的不重做
python tools/tts/vo_qa.py videos/<名字>/lines.js videos/<名字>/vo --model medium
python videos/<名字>/vo.py                         # 写 vo-d.js（每句时长）和 vo-env.json（响度包络）
```

- 读错的句子：`vo_all.py <名字> --only L08 --take 2`（换种子另出一条，不覆盖），质检用 `--take 2` 看，好的那条复制成 `L08.wav`。
- 识别模型自己也会错：短句（四个字以内）、同音字、句尾多出一个音，换一个识别模型（`--model turbo` / `medium`）再看一次；两个都说错才算错。把拿不准的句子的秒数告诉对方。
- 没有显卡或想用别的引擎：任何 TTS 都行，只要每句出一个 `<id>.wav` 放进 `videos/<名字>/vo/`。

默认引擎是 Qwen3-TTS（Apache 2.0，`pip install qwen-tts`；`torch` 和 `torchaudio` 版本要一致）：Base 模型照参考说话，VoiceDesign 模型按描述造声音，各约 4 GB，显存峰值约 4.6 GB，约 2 倍实时。质检用 openai-whisper + pypinyin + cn2an。8 GB 显存放不下两个模型同时跑，也别和游戏一起跑。

## 为合成声音写台词

- **一行一条音频、一口气。** 一行 20–70 个字最稳；更长的拆成两行。
- 停顿不靠标点堆，靠行与行之间的间隔（`lines.js` 第二列，毫秒）：块内 300–500，块与块之间 1000 上下，另一个声音开口前后 500–900。
- 数字写汉字（七点十五）；英文词和缩写保留原样，但要请人听读得怪不怪；容易吞字的词改写法或加逗号。
- 字母缩写（RAG、API）常被一个字母一个字母念：口播换成中文说法（「检索增强」），缩写写在画面上。英文人名、产品名念不准就换种子重出；还不行，口播只说身份（「Terraform 的作者」），名字写在画面上。
- 多音字放在生词组里容易读错（「清空重来」的「重」读成 zhòng）：换一个不含多音字的说法（「从头再来」）。`vo_qa.py` 的「多音字待查」只能提示识别模型写成了别的字的情况，同一个字读错了声调它看不见，关键句要请人听。
- 括号不进台词（会念出怪音）。引号和书名号可以留在 `lines.js` 里给字幕看：`tts_text()` 送去生成之前会把「」『』“”《》去掉。
- 不为了对上时长去拉伸、改音调——听得出来，「声音发假」。语速不对就改字数或换种子。（故意让声音听起来像虚拟角色是另一回事，见下面「给声音加角色感」。）
- 合成声音读不出反讽，也读不好一两个字的语气词。句子要字面上就成立。
- 被打断的半句话：照写半句，下一行用负的间隔叠上去。

## 给声音加角色感（电音）

讲述者是虚拟角色（吉祥物、AI、物件）时，一个干净的合成人声会让它听着像一个真人在念稿。生成之后过一遍 `voice_fx.py`：

```bash
python tools/tts/voice_fx.py --list                                   # 档位：deeper · virtual-light · virtual-mid · virtual-strong · robot
python tools/tts/voice_fx.py --compare <名字> L04 L19                  # 同两句出全部档位，放进对比页给人挑
python tools/tts/voice_fx.py <名字> --voice L --preset virtual-mid     # 整条片子的 L 都处理；或者在 voices.json 里给声音写 "fx"
python tools/tts/vo_qa.py videos/<名字>/lines.js videos/<名字>/vo       # 处理完再核对一遍：字还要听得清
python videos/<名字>/vo.py
```

- 做了什么：音高和共振峰一起往下压一点（装了 `praat-parselmouth` 时两者分开调，更自然）；叠一层声码器，载波跟着这句话自己的音高走、吸附到半音上（「电音」那种被调过音的质感）；一点合唱、一点数字颗粒。干声仍然是主体，负责让字听清。
- 原声留在 `videos/<名字>/vo/raw/`，再跑一次总是从原声重新处理；某句重新生成过（`vo_all.py --overwrite`）会被认出来，当作新的原声。
- **档位要人来挑**：你听不见。用 `--compare` 出对比，做一页试听给对方，片子先用 `virtual-mid`。处理后的识别准确率要和原声差不多；变差了就降一档。

## 接进片子

`vo.py` 读 `lines.js` 里的 id，从 `videos/<名字>/vo/` 取 wav，裁掉首尾静音、统一响度，写出每句的时长和包络。场景按真实时长串时间轴，字幕跟着包络一个字一个字出，角色的嘴（或锅盖）跟着包络动。某一句还没有音频时，场景按字数估时长，照样能跑。
