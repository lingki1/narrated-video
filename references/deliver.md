# 预览、渲染、发布

## 预览（带声音，先给人看这个）

先 `node render.mjs videos/<名字> --sound-only` 出声音，然后三种看法：

| 对方在哪 | 做法 |
|---|---|
| 就在这台电脑前 | 在项目文件夹里起一个只绑本机的静态服务（`python -m http.server 8080 --bind 127.0.0.1`），打开 `http://127.0.0.1:8080/videos/<名字>/index.html?play`。点一下开声音，空格暂停，← → 快退快进 |
| 同一个 Wi-Fi 下的手机 | `python tools/lan_preview.py <名字> --host <这台电脑的局域网地址>`，手机打开它打印的地址。它只放行这一条片子、`lib/` 和它的配乐，别的一律 404 |
| 不在一个网络里 | `python tools/artifact_preview.py <名字>` 打包成一页带播放器的网页（`videos/<名字>/out/artifact/page.html` + `files.json` 里列的文件），发布到你手头能发私有网页的地方（例如 Claude 的 Artifact：页面用 `page.html`，`files` 照 `files.json` 填）。同一个路径再发一次就是更新，链接不变 |

- **不要**为了给人看而对局域网或公网开整个项目文件夹：里面可能有密钥、参考音频、没发的稿子。也不要去改防火墙或路由器；那是机器主人的事。
- 预览服务要自己开一个窗口跑；借助某些工具起的服务会被自动停掉。
- 给链接的同时说清楚：怎么开声音、片长、哪些地方请他重点听、怎么报问题（秒数）。

## 渲染（对方说「可以了」之后）

```bash
node render.mjs videos/<名字> --blur 3        # 后台跑；约 0.1 秒一帧，四路并行
```

- 输出 `videos/<名字>/out/<名字>.mp4`（H.264，1080×1920，30 fps，响度归一到 −14 LUFS）。`--blur 3` 是动态模糊（每帧取 3 个子帧平均）。
- 渲完核对：时长、分辨率、有音轨；抽几帧看；和预览对一下最后一句的时间。
- 对方说停就停，并确认没有残留的浏览器和 ffmpeg 进程。
- 太大要压：`ffmpeg -i 母版 -c:v libx264 -crf 21 -preset slow -c:a copy 上传版.mp4`。
- 封面：**单独设计，不抽帧**。三个概念、三种画布、缩小检查、找没看过的人看一眼，做法在 `references/cover.md`。发布包里写清哪个平台传哪个文件、每张配哪个标题。

## 发布（每一次都要对方点头）

- 文案、话题标签、替代文本先给对方看。
- 平台要求的标注照做（AI 生成内容、广告）。
- 发出去的东西会被缓存和转发，删了也收不回；所以发布、置顶、改公开范围，都等对方明确说了再做，而且一次同意只管这一次。
- 发完把链接、时间、平台记进 `videos/<名字>/docs/<名字>.md`。过几天把数据（完播、收藏、评论里的原话）也记进去，写进 `PROFILE.md` 末尾的表：下一条的选题从这里来。

## 存档

对方看过的版本要留：改大方向之前把这条片子的画面文件复制一份到它自己的 `archive/code-<版本>/`，配音复制到 `archive/vo-<版本>/`（要重新跑旧版，再把它复制回 `videos/<名字>-<版本>/`）。不删对方的文件；要清理就挪到一个「待删除」的文件夹里，把删除命令给他自己跑。
