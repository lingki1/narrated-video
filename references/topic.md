# 选题

## 一条片子 = 一件小事 + 一个在场的讲述者

- **一件小事**：能用一句话说清「谁、哪天、出了什么事」。大题目（独居、加班、AI）不是题，是背景；题是「凌晨一点四十她到家，掀开锅盖，饭还是热的」。
- **讲述者在场**：这件事只有他知道、他看见了、他在乎。讲述者可以是人，也可以是一样东西——电饭煲、闹钟、楼下的快递柜、一件穿旧的衣服、手机里的助手。物件当讲述者时，陪伴感来自三件事：它在场、它看见了、连当事人自己都忘了。不来自它好笑。
- **讲述者见识有限**：他只会那么几件事、只看得见那么一小块世界。认真地用这点见识去理解别的事，就是幽默的来源；最后他弄明白了一点，就是结尾。
- **观众认得出自己**：这件事里要有一两处让人说「这个我也干过」的细节。

选题时问四个问题：
1. 这件事讲的人「在乎」吗？他在乎什么、怕什么？
2. 有没有一个钟点、一个地方、一两样指得着的东西？
3. 事情往下走的时候，是不是一层比一层深（不是并列的几个例子）？
4. 讲完以后，他变了什么？（哪怕只是不打算再遵守说明书的某一条。）

四个里答不上两个，换题。

## 先查，再定

- 读项目的 `PROFILE.md`：给谁看、他们最近在说什么、不能碰什么。记录过期了就重查。
- 查当下的热点和这群人的吐槽（搜索 + 读媒体转述）。热点是背景和细节的来源，不是片子的全部：借它的一个真实细节（排到第 99 号、堵了五个小时），讲的还是自己那件小事。
- 查到的东西写进 `videos/<名字>/docs/<名字>.md`：来源链接、日期、哪些是原页核对过的、哪些只见摘要。读页面的工具会编造，「某某说过某句话」核对不了就别用。
- 只用搜索和阅读；遇到登录墙、验证码、反爬页面就跳过，不绕。

## 真和编

- 故事可以编，编的要写明（片尾小字「故事是编的」）。
- 片子里**当成真的**给人看的东西必须是真的：数据、别人的原话、产品的演示、某个模型的回复。要用就原样用，并且留得下出处；拿不到真的，就换成明显是示意的画法，或者不用。
- 不替任何人说他没说过的话；不点名真人和别家产品来开玩笑或拉踩。
- 讲述者吹的牛、出的丑，不能是这个项目要卖的东西本身——观众会只记住「它不行」。
- 平台要求的标注（AI 生成内容、广告）照做，写在片尾。

## 时效

热点类的片子从选题到发出去最好在三天内；过了一周，换成不靠热点也成立的讲法。
